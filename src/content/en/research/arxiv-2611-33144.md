The data problem in dexterous manipulation is well rehearsed. Human video is cheap but retargets imprecisely; teleoperation is accurate but the operator gets no force feedback and guesses at finger pressure; exoskeletons capture force but do not scale. All three routes share one assumption — that a human must perform the task first. PyRUA-Dex drops that assumption and has coding agents write the control program directly.

The framework runs in two stages. In exploration, several agents work in parallel, some searching for reusable task skills and others testing how those skills compose into complete solutions; a distilling agent then collapses the successful attempts into a task library plus one program. That stage answers whether the task can be done at all. Refinement answers whether it can be done reliably and quickly: the program is re-executed under randomized layouts so that it survives perturbation, while execution time is squeezed down. No human demonstration trajectories are involved anywhere; the learning signal comes from the agents' own trial and error over code.

Program-as-policy has an underrated property: failures are attributable. When the policy is code, an error can be traced to a specific skill call, parameter or timing assumption instead of being interrogated inside a black-box network. A shared task library also means new tasks can reuse old components rather than retraining from scratch.

The numbers are strong. PyRUA-Dex scores 72.9 on Bench2Dex and reaches 81.0% success on DexJoCo under full randomization, which the paper reports as ahead of every trained policy on both benchmarks — a demonstration-free recipe that is no longer behind data-driven methods on standard dexterous leaderboards. The hardware results make the point harder to dismiss: on a bimanual platform with two 22-DoF hands the system learns piano, calligraphy and other tasks, picking up a new piece from sheet music in as little as 30 minutes. At that timescale the marginal cost of a new skill lands near a single debugging session rather than weeks of collection and annotation.

The caveats are real. Programmatic policies inherit the accuracy of perception and state estimation — if finger pose or contact state is misjudged, flawless code execution still fails, and the abstract offers no sensitivity analysis on perception error. Evaluation concentrates on Bench2Dex, DexJoCo and a small set of real tasks, so cross-object and cross-scene generalization remains thinly evidenced. The search cost of the coding-agent loop — how many parallel attempts, distillation passes and refinement rollouts each task consumes — is not quantified, and that cost is exactly what determines whether the approach is reproducible outside a well-resourced lab. Finally, "learning from sheet music" implies the task arrives already structured; whether the same holds for long-horizon tasks without clean stage boundaries is untested.

The industrial reading is straightforward: if programmatic policies can acquire new skills on real hardware at hour-scale cost, the value in dexterous manipulation shifts from training a model to maintaining a skill library and an execution stack. That matches where humanoid vendors are already heading, treating new tasks as configuration rather than as training projects.
