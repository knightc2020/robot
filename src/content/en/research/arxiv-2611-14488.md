Long-horizon manipulation asks a policy to remember what just happened: whether the cup is already grasped, how far the drawer was pulled, whether the previous attempt needs a retry. Memory-augmented vision-language-action models exist for exactly this, keeping a window of past frames in context so the policy can look back before acting. What gets remembered, and how it is indexed, has largely been treated as an implementation detail.

This paper asks an uncomfortable question about that detail. If memory is built by sampling frames uniformly in time and stamping each one with its time step, the memory encodes a clock rather than a sequence of events. Time passes whether or not anything happens, so such a memory cannot tell waiting from working. The authors name the resulting failure phantom progress: the policy believes it has advanced the task and terminates early.

### Core innovation

The contribution is not a new model but a well-designed causal diagnosis. On the counting tasks of RoboMME, the authors inject a null event: the robot pauses briefly, or merely fidgets its wrist. Neither changes anything the task depends on. A released memory VLA nevertheless counts the interval as work completed and stops.

The decisive control is that withholding those same frames from memory restores success. The interruption itself is therefore not the cause; what memory absorbed is. The authors then trace the mechanism to a temporal shortcut. Demonstrations proceed at a steady pace, so elapsed time is an almost perfect predictor of progress within the training distribution. Rescaling the time stamps alone reproduces the pathology in both directions: run the clock fast and the policy stops early, run it slow and it repeats work.

That yields a counterintuitive finding. Removing the time encoding does not cure the failure, because the frames of a null event still occupy slots in a time-sampled memory. The model can infer that time has passed from the simple fact that slots are full. The defect lives in the indexing scheme, not in the feature content.

The repair comparison is equally useful. Training with injected pauses, the first thing most engineers would try, neither removes the failure nor leaves counting intact. Indexing memory by events, which requires changing how memory is organised rather than retraining the network, recovers half or more of the lost success. Across RoboMME's released designs, vulnerability tracks how memory is indexed, which closes the causal loop beyond a single architecture.

### Results

The quantitative core is two counting tasks: after the null event, success drops from 47 to 16 of 50 trials on one and from 44 to 10 on the other. The absolute numbers matter less than their shape. A perturbation carrying no task-relevant information removes more than half the successes, which means the policy's reliance on time is strong enough to be attacked at a single point. Restoration after withholding the frames supplies the exclusionary second line of evidence.

In the repair comparison, event-indexed memory recovers at least half the loss with no retraining, while pause-augmented training fails on both counts and damages existing counting ability. The time-stamp rescaling experiment is the most persuasive part of the paper because it isolates the mechanism under direct control.

### Limitations

Evaluation stays within the counting tasks of one benchmark, with tens of trials per condition, so statistical power is limited. The abstract does not say what supplies the event segmentation that event-indexed memory requires, and event boundaries in real data are far blurrier than in a benchmark. If event detection is itself learned, the fix introduces a new failure surface. All evidence is simulated; no physical long-horizon task is reported, and sensor noise, human intervention and irregular pacing could all change how strongly the shortcut manifests on hardware. The study also covers released memory designs, leaving open whether the conclusion holds for architectures that use learned memory compression rather than frame buffers.

### Industry implications

For teams shipping long-horizon VLA systems, the first recommendation is about evaluation: add null events, pauses and idle motion, to regression suites. It costs almost nothing and surfaces a class of brittleness that aggregate success rates hide completely. The second is about data: if demonstrations were collected at an unusually regular pace, the policy will learn that time equals progress, so collection protocols should deliberately vary pacing.

The deeper implication is architectural. How memory is indexed is a product decision, not an implementation detail. Time-indexed memory answers the question of what happened recently; event-indexed memory answers the question of what has been accomplished. The failure mode of the former is nearly invisible in demo footage, because the robot simply stops early and the run looks like a completion. That kind of silent failure is the most dangerous one in deployment, and as the field starts to write reliability targets for long-horizon tasks, memory indexing looks likely to become a specification item rather than an afterthought.
