Robot manipulation has settled on writing skill into network weights: collect demonstrations, run gradient updates, and hope the deployment world resembles the training distribution. The resulting competence is tied to that distribution, and a new scene or a new camera can break it. In-context learning offers an alternative — leave the weights alone and put the demonstration in the prompt — but it has never matched trained policies. The reason is intuitive: a demonstration recorded in another scene carries no feedback from the world the robot currently faces.

This paper starts from an observation: what an agent learns in context is semantic. It records task steps and object roles, not visual appearance. Experience gathered in one world can therefore transfer to another. The authors call the resulting paradigm World In-Context Learning (WICL): a frozen model starts from a demonstration, rehearses the task in a world such as a simulator, and writes the feedback into its context instead of its weights. RoboScript is their modular infrastructure for implementing it.

### Core innovation

WICL moves the locus of learning from parameter space to context space, and uses an explicit world interaction to supply the feedback a demonstration lacks. The pipeline has three stages: a single demonstration supplies task semantics, simulation rehearsal produces local evidence about what happens when the task is attempted, and a Task Memory freezes the rehearsal result for reuse at deployment.

The engineering constraint in RoboScript matters as much as the paradigm. Every deployment input must be available on a real robot, a data-isolation rule that prevents simulated privileged information from leaking into physical execution. When the system moves to a new scene it reuses the frozen memory rather than retraining. The paper also demonstrates cross-embodiment memory adaptation, letting one memory serve different dual-arm platforms.

The implication runs against the usual scaling story: capability can grow with a stronger foundation model and more rehearsal, without more teleoperated data. For teams trying to cover long-tail tasks quickly, the data-cost structure is fundamentally different.

### Results

Evaluation covers all 50 tasks in RoboTwin 2.0, with one demonstration per task and no gradient updates. Mean success reaches 83.4% across clean and randomized settings, more than 20 percentage points above the strongest trained action policy.

The paper reports four generalization properties: the method holds across visual distributions, improves through reflection, scales with the foundation model, and transfers to a physical dual-arm robot via cross-embodiment memory adaptation. Code is released on GitHub, giving reproducibility a concrete entry point.

### Limitations

The abstract gives no real-robot success rate; the physical transfer reads as a feasibility demonstration rather than a controlled comparison against trained policies. The 83.4% is a mean over 50 tasks with no per-task variance, confidence intervals, or seed count. The method depends on a usable simulator, and the sim-to-real gap enters Task Memory directly. Rehearsal and reflection add inference and simulation cost that the paper does not price. The data-isolation rule improves real-robot validity but also caps which simulated information can be exploited.

### Industry implications

The industrial significance is less another manipulation model than a change in deployment economics. If one demonstration plus a rehearsal pass can reach usable success on a new task, the bottleneck for expanding a robot's task list shifts from data collection to simulation assets, memory management, and closed-loop reasoning. That matters most for dual-arm and humanoid platforms: cross-embodiment memory adaptation means the same task experience can survive a hardware generation change instead of forcing a fresh data campaign. The open questions are long-run reliability on real hardware and whether rehearsal cost can be pushed low enough for online deployment.
