Visual localization in a mapped building is usually built on two assumptions that fail in the same shift. The first is that a small set of reference images captured on survey day still describes the place. The second is that the right reference can be found by matching appearance, which stops working when a corridor is repainted, when two aisles look alike, or when a crowd of people occupies the frame.

MERLoc starts by replacing the sparse cache with a dense one. A single metric 3D Gaussian Splatting scan of the space is turned into what the authors call a Functional Reference Memory: reference views are sampled over the navigable area at a chosen density, respecting where the robot's body and sensors can actually be, and rendered offline from the splat. Those views are then pre-encoded for whichever off-the-shelf localizer will be used at runtime, which removes the reference encoder from the inference path entirely — the expensive half of the comparison happens once, before deployment.

The second change is what makes the density affordable. Because the memory is indexed by where each view was rendered from, retrieval can be driven by the robot's prior pose and heading rather than by image similarity: fetch the references that were rendered near where you think you are, looking the way you are looking. That sidesteps visual ambiguity by construction in any situation where a prior exists, which for a robot operating in a mapped space is most of the time.

The evidence is broad rather than anecdotal. One classical and four learned localizers are each tested in simulated and real dynamic scenes; pose-based retrieval matches or beats appearance retrieval in most configurations, and does so even when appearance retrieval is given the same pose prior as a gate — a fair control that rules out the trivial explanation. On real data, position RMSE falls by 15% to 60% in nine of the ten backend and split combinations. The rendered memory also outperforms real-image caches posed by Structure-from-Motion, which matters because re-surveying a building with a camera rig is exactly the operational cost that map-based deployments want to avoid.

Then comes the part that decides whether this is a paper or a product: the whole pipeline runs at 5 Hz on a Jetson Orin NX, and a navigation policy uses it to cross a hallway with people walking through and objects being moved. That is the actual failure mode in a live warehouse or hospital corridor — not a static benchmark, but a crowd that fills the field of view and a floor that no longer matches the survey.

The honest limits are the ones implied by the design. Pose-based retrieval presupposes a pose; for global localization on startup, kidnapped-robot recovery, or a prior that has drifted badly, the mechanism has nothing to index against and the paper does not say how the system recovers. Accuracy also inherits the metric fidelity of the Gaussian Splatting scan and the quality of the pre-encoding, and a dense rendered memory costs storage and one offline render pass per site. Evaluation concentrates on hallway-scale indoor traversal, so multi-floor, outdoor or highly reflective environments remain untested, and the failure behavior when a prior is confidently wrong is not characterized.

For AMR fleets the operational reading is direct. The recurring cost of map-based navigation is keeping the reference set current, and a single splat scan that can be re-rendered and re-encoded makes that a batch job instead of a survey crew. If the accuracy holds outside hallways, the practical result is a robot that keeps localizing on the day the racks get rearranged — which is most days.
