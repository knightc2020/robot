多模态模型现在已经能零样本从图像直接操控机器人，这个演示足够有说服力，以至于剩下的缺口一眼就能点出来：图像里没有力。凡是涉及按压、插入、擦拭、递接的任务，都依赖一个模型看不见的量；只看得见像素的策略，会一直推下去，直到东西坏了或者滑脱。

最直觉的补法是「把力也作为输入喂进去」，但这条路上有两个坑，这篇论文都认真处理了。第一，接触发生在毫秒尺度，而 API 模型返回一次决策要几百毫秒；等模型回来再对力尖峰作出反应，已经晚了。第二，冻结模型根本不知道一串原始力数据该怎么用——给它一串牛顿值，它既没有标定、也没有单位，更不知道这个夹爪抓这个物体时什么数值算合理。

### 核心创新

ForceHarness 的定位是「外壳」而不是「模型」，它的设计直接由上面两个约束推出来。

为了让闭环快过模型的决策节奏，作者提出了自终止力原语。每个原语都是一段短的、参数化的力行为——压到某个阈值、维持某个载荷、在接触事件发生时回撤——它自己完成力的调节，并在等到目标接触事件时把控制权交还给模型。于是力在控制频率上于原语层闭环，模型只负责离散决策：用哪个原语、参数取多少、拿到结果之后做什么。

为了让冻结模型「读得懂」力，物理翻译层把每段力曲线转换成带不确定度的物理量，作为工具调用的返回值交给模型。模型看到的不是原始传感器数值，而是类似「估计接触力 X，置信度 Y」这样它能够推理的东西。标定单独处理：有腕部力传感器时从传感器恢复手部力，没有时则仅靠关节力矩。

作者还构建了 HiddenPhys——一个包含七类任务的 MuJoCo 基准，其中质量、摩擦、柔顺性等物理量对策略是隐藏的。之所以要新建基准，是因为现有的力控基准测不到这里最关键的能力：系统能否从接触中推断隐藏的物理状态，而不是背下一条轨迹。

### 结果

最醒目的数字来自真机。在一台没有腕部力传感器的真实机械臂上，ForceHarness 把 GPT-6 Astra 的零样本成功率从 3.3% 提升到 90.0%。这个结果里有两件事比绝对值更重要：力是从关节力矩估出来的，没有加任何硬件；整个过程没有微调，模型权重与 API 上的完全一致。

仿真里，该方法在公开的 ForceBench 上提升 17.5 个百分点，在 HiddenPhys 上提升 34.3 个百分点。两个基准上都超过了用示范训练过的力感知策略；在 HiddenPhys 上则与人工编写的专家控制器持平。用「冻结的通用模型 + 外壳」打赢专门训练的专家策略，是全文最强的主张，因为它说明瓶颈在接口设计，而不在策略容量。

消融实验给出的结论最具可迁移性：当输入是物理量而不是原始力值时，较小的模型做出的决策明显更好。这说明翻译层不是给弱模型准备的便利，而是「能不能用力」的前置条件。

### 局限

这套方法的能力其实长在原语上。「压住并保持」对插入和擦拭是很好的抽象，但当有用的力曲线本身就是需要被发现的东西时——比如操作一个柔顺性会随形变而改变的物体——它怎么扩展并不清楚。

仅靠关节力矩标定是一种近似，而真机证据只有一条机械臂上的一个任务。带减速器、摩擦与背隙都不小的工业臂上，力矩估计是否还站得住，是开放问题；而那里的失效是安静的：模型会收到一个自信但错误的物理量。

HiddenPhys 是七个任务的仿真基准。它的动机很扎实，但规模小，而接触的仿真到现实迁移恰恰是力模型最薄弱的地方。

### 产业启示

最直接的含义是：「冻结 API 模型」这套架构比看上去能打得多。因为成本、权限，或者干脆因为模型是别人的产品而无法微调的团队，依然可以通过投入外壳——原语、标定、翻译层——拿到接触密集的行为。这些都是机器人团队本来就擅长的工程，不需要训练集群。

第二层含义关乎价值沉淀在哪里。如果把这个通用模型变成合格操作器的是外壳，那么真正持久的资产是原语库和标定流程，而不是策略权重。对机器人产业来说这是一种更熟悉的护城河，而且它有利于有真实硬件经验的团队，而不是只有模型访问权的团队。
